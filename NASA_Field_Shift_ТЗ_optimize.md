## Частина A. ТЗ

### A1. Що робить модуль

Для обраного поля система рекомендує, **що сіяти в наступному сезоні**, і складає **календар сівозміни на 3–4 роки**. Для кожної стратегії показує:

1. **Скільки буде врожаю** кожної культури, т/га і т на поле, у сухий, типовий і вологий рік.
2. **Куди вигідніше продати**: місцевий елеватор, порт чи переробник, з урахуванням доставки.
3. **Чи вигідніше згодувати худобі** і продати м'ясо, ніж продати зерно.

Порівнюємо мінімум 3 стратегії: поточну (з HLS, підтверджену фермером) і 2–3 альтернативи з фронту Парето.

Інструмент **підтримує** рішення фермера й агронома і не замінює їх. Кожне число має діапазон і джерело.

> Відповідність челенджу: пп. 1 і календар — ядро. П. 3 закриває пріоритети «кормова цінність» і «ринок» з тексту завдання. П. 2 — це обмеження «ринок»; він опційний, але дає сильну історію для журі (логістика у воєнний час).

```text
профіль поля ──► 1 ГЕНЕРАЦІЯ послідовностей (3–4 роки, ~15 культур + пар)
(POWER, SMAP,     2 ФІЛЬТР: норматив №164, матриця попередників, попередник поля, техніка
 ґрунт, HLS)      3 СИМУЛЯЦІЯ: simulate_sequence на всіх 25 роках погоди → розподіл т/га
                  4 ЗБУТ: для кожної культури × року — max(продаж у точці j − доставка, корм → м'ясо)
пріоритети   ──►  5 ОЦІНКА: дохід P50, дохід P10, вода, ґрунт, самозабезпечення кормом
фермера           6 ПАРЕТО → 3 стратегії + поточна → пояснення
```

### A2. Культури (розширений список)

Агент перевіряє наявність параметрів **у першоджерелах** і заповнює `model/crops.yaml`. Якщо параметра немає в джерелі, ставить TODO і культура блокується. Підставляти значення «з голови» заборонено.

| Група | Культури | Звідки параметри |
|---|---|---|
| Зернові озимі | пшениця озима, ячмінь озимий, жито | Kc: FAO-56 табл. 12; Ky: FAO-33 табл. / FAO-66 |
| Зернові ярі | ячмінь ярий, овес, пшениця яра | те саме |
| Пізні ярі | кукурудза на зерно, соняшник, сорго, просо | те саме |
| Бобові | соя, горох, нут | те саме (нут — перевірити наявність) |
| Олійні | ріпак озимий, льон | Kc: FAO-56 (canola, flax); Ky — перевірити |
| Технічні | буряк цукровий | FAO-56 / FAO-33 |
| Кормові | люцерна (багаторічна), кукурудза на силос | FAO-56; Ky — FAO-33 (alfalfa) |
| Без культури | чорний пар, сидерат (гірчиця/редька) | Kc_bare / Kc для покривної культури — FAO-56 розд. 11 |

Для кожної культури в YAML: Kc (ini/mid/end), довжини фаз, Ky, Zr, p, календар по зонах (степ / лісостеп / полісся), група нормативу №164, строк повернення, азотфіксація (так/ні), кормова цінність (див. A5), джерела. Календар сівби і збирання беруть R2/R3 з рекомендацій НААН по зонах, а агент лише перевіряє формат.

### A3. Врожай (п. 1)

- `simulate_sequence(field, crops, start_year)` проганяється для **кожного з 25 років погоди 2001–2025 як стартового** (зсув ряду, волога переноситься між сезонами). Результат — розподіл врожаю для кожного року сівозміни.
- т/га = Yx · Ya/Yx, де Yx — P90 обласної врожайності Держстату для пари культура × область (leave-one-year-out під час валідації).
- **Ефект попередника**: у першу чергу через водний баланс (фізика). Додатково — множник `prev_effect[попередник][культура]` з `rules.yaml`, лише із джерелом. Без джерела множник = 1,0 з прапорцем «не враховано».
- Вихід: P10 / P50 / P90 т/га, а також т на поле (площа з NASA Harvest).
- Якщо культура не має обласної статистики Держстату, Yx = TODO, і в UI з'являється позначка «немає даних для калібрування».

### A4. Збут: продаж і доставка (п. 2)

`data/market/buyers.csv` — заповнюють люди, агент формат лише перевіряє:

```text
buyer_id, type (elevator|port|processor|feed_mill), name, lat, lon, crop, price_uah_t, basis (EXW|CPT|FCA), date, source
```

`data/market/transport.yaml`: тариф авто, грн/т·км (+ фіксована ставка), коефіцієнт «дорога / пряма» (за замовчуванням TODO; виміряти на 5–10 маршрутах), джерело.

- Чиста ціна в точці j: `price_j − tariff · dist_road(field, j) − fixed`; відстань = haversine × коефіцієнт.
- Для кожної культури обираємо найкращу точку. Показуємо топ-3 точки і **точку беззбитковості**: на якій відстані порт програє місцевому елеватору.
- Ризики (текстом у поясненні, без цифр без джерела): робота портів, сезонні пікові тарифи, якість зерна.
- Якщо цін немає — модуль вимкнено і використовується одна ціна з `prices.csv`. UI показує «логістику не враховано».

### A5. Збут через тваринництво (п. 3)

`model/livestock.yaml` — заповнюють люди, агент формат лише перевіряє:

```text
species: pig | broiler | beef | dairy (опційно)
feed_conversion_kg_feed_per_kg_gain, liveweight_price_uah_kg, carcass_yield,
max_share_in_ration (по культурах), протеїн/енергія корму (ME МДж/кг, CP %) по культурах, source
```

- Канал «корм»: т зерна → кг приросту (за FCR і обмеженням частки в раціоні) → грн. Виробничі витрати тваринництва, крім корму, — TODO з джерелом. Без них підписуємо «валовий дохід від м'яса, без витрат на утримання».
- Для кожної культури × року канал = `max(продаж, корм)`. Показуємо, що обрано і чому.
- Для фермерів із худобою — додатковий критерій: **самозабезпечення кормом** (частка потреби в енергії й протеїні, закрита з власних полів). Тут люцерна, горох, соя і силос починають конкурувати з соняшником.

### A6. Фільтри (жорсткі правила) — `rules.yaml`

1. Норматив №164: строки повернення (уже реалізовано на сайті — перенести логіку, не дублювати по-іншому).
2. Матриця попередників НААН по зонах: «добрий / допустимий / поганий». «Поганий» — це штраф або фільтр за налаштуванням.
3. Попередник поля = останній рік HLS + підтвердження фермера. Якщо він не підтверджений — розглядаємо обидва варіанти (озима / ярова) і показуємо, як змінюється рекомендація.
4. Обмеження фермера: доступна техніка (наприклад, немає кукурудзяної жатки), заборонені культури, мінімальна частка культури.

### A7. Оцінка і вибір

Критерії для кожної послідовності (розподіл за 25 стартовими роками):

- дохід за ротацію P50, грн/га/рік (з урахуванням каналу збуту);
- дохід P10 (сухий рік) — ризик;
- вода: середній дефіцит ETc − ETa і запас вологи на кінець ротації;
- ґрунт: частка бобових, дні голого поля, частка культур, що сушать ґрунт (соняшник);
- (за наявності худоби) самозабезпечення кормом.

Вибір: недоміновані послідовності (фронт Парето) → ваги з повзунків фермера → 3 стратегії: «макс. дохід», «мін. ризик», «баланс / ґрунт». Повний перебір 3–4-річних послідовностей із ~16 варіантів після фільтрів має вкладатися в секунди. Метаевристика (ABC / генетичний алгоритм) потрібна лише для 5+ років; її результат порівнюємо з перебором.

### A8. Календар сівозміни (3–4 роки)

`calendar` у `strategies.json`: для кожного року і культури — дати сівби, ключових фаз і збирання (із `crops.yaml` по зоні поля); вікна голого поля; вікно для сидерату; позначки ризику (спека в цвітіння, заморозки після сходів — лічильники з симулятора, P50 і P90 днів). На фронті це діаграма Ганта по місяцях.

### A10. Валідація

1. Юніт-тести: фільтр №164 збігається з логікою на сайті (6 прикладів-пресетів); чиста ціна та вибір каналу на ручних прикладах; баланс маси в послідовності.
2. Hindcast «поточної» стратегії: модельний врожай фактичної послідовності поля проти аномалій Держстату (області пілотів).
3. Чутливість: як змінюється топ-3 при ±20% ціни, при ±1 у коефіцієнті дорога/пряма і при виключенні ефекту попередника. Результат — у `reports/sensitivity.md` (це прямо відповідає вимозі «make uncertainty visible»).
4. Перебір проти метаевристики: однаковий фронт на 3–4 роках.

### A11. Обмеження

- Python 3.11+, numpy, pandas, pyyaml, scipy, pytest. Без мережі в `optimize.py`.
- Жодних агрономічних, економічних чи зоотехнічних чисел без джерела в YAML/CSV. Якщо параметра немає — помилка або прапорець, а не мовчазне значення за замовчуванням.
- Усі суми підписані: «валовий дохід», «без витрат на …».
- До хакатону: пп. A2 (мінімум 8 культур + пар), A3, A6, A7, A8. Пп. A4–A5 — каркас і формати; числа вносять люди, коли знайдуть джерела.
